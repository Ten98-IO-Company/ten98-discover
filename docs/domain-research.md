# Domain SEO reports

This P49 increment adds manual organic domain overview, top pages and organic competitors to the existing ranked-keyword lookup. It is separate from serving-domain configuration and native Google imports. [Backlink research](backlink-research.md) adds two separate DataForSEO profiles through the same native receipt flow; their URL scope rules differ from organic research. Optional Ahrefs rating, unrestricted upstream datasets and the remaining P49/P52 acceptance are still required. No score is inferred from keyword or traffic estimates. This is not complete OpenSEO parity.

## Scope and display

The selected target, scope, location/language and maximum25/50/100 results form an immutable quoted request. **Domain and subdomains** includes the named hostname and descendants; **Domain only** pins the named hostname, treating its `www.` alias as equivalent. **Subfolder** includes the chosen path and descendants with a path boundary; **Exact URL path** includes the exact path and its trailing-slash variant. The OpenSEO89e5 scope convention ignores query strings, fragments and HTTP/HTTPS differences, canonicalizes IDNs and treats leading `www.` as an alias. The screen discloses the canonical target before a quote and again before paid Start. Subfolder requires a non-root path. No DNS lookup or target-page fetch occurs.

The fixed request is DataForSEO Labs Google `ranked_keywords/live`, organic items only, live historical mode, offset0, clickstream disabled, absolute rank enabled, estimated-traffic descending then keyword ascending. Scope filters precede provider results; every returned URL is independently checked against the selected scope. Literal percent, underscore and backslash filter operators are escaped. A report shows returned count, provider total count and explicit partial status. A first page is never called a complete inventory when more results exist; no automatic paid pagination occurs. Provider estimates are not native visits or traffic measurements. Missing metrics are null; genuine0 remains0. CPC is exact micro-USD text, not an account charge.

The fixed endpoint and its limits/filter/tag contract are documented in [DataForSEO Ranked Keywords](https://docs.dataforseo.com/v3/dataforseo_labs-google-ranked_keywords-live/). Account-specific base per-request/per-result pricing comes from the free [User Data endpoint](https://docs.dataforseo.com/v3/appendix-user-data/); optional paid parameters are not inferred from those base prices and remain disabled. No fixed public price is hardcoded.

## Three additional fixed profiles

For organic research, `report` is optional. Omitting it preserves the existing ranked-keyword request, ledger operation, tag and result shape. `overview_v1`, `pages_v1` and `competitors_v1` freeze the additional organic payloads and metric meaning without changing old receipts. The separate Backlinks request union is documented in [backlink research](backlink-research.md). Each report needs its own quote and explicit Start. Opening a receipt, selecting a report or following a detail action never purchases another report.

| Profile | Fixed endpoint and population | Returned dataset |
|---|---|---|
| `overview_v1` | [Domain Rank Overview](https://docs.dataforseo.com/v3/dataforseo_labs-google-domain_rank_overview-live/), one selected market, domain and subdomains, limit1 | Organic ranking-keyword count, estimated monthly traffic, equivalent ads value in USD and12 position buckets |
| `pages_v1` | [Relevant Pages](https://docs.dataforseo.com/v3/dataforseo_labs-google-relevant_pages-live/), organic/live, all four explicit scopes, first25/50/100 sorted by estimated traffic then URL | URL and the same organic metric fields for each page |
| `competitors_v1` | [Competitors Domain](https://docs.dataforseo.com/v3/dataforseo_labs-google-competitors_domain-live/), organic, domain and subdomains, top100 rank groups, first25/50/100 sorted by keyword intersections then domain | Competitor domain, shared keywords, competitor average position on shared keywords, competitor-wide organic metrics, separately labeled target metrics on shared keywords |

The overview and competitor APIs cannot filter their target to a single hostname, folder or exact path. Their input therefore requires explicit `subdomains` scope; narrower scope requests fail before pricing or dispatch. Top pages uses escaped `page_address` LIKE filters with at most8 conditions, including query and trailing-slash variants, followed by an independent URL scope check. No regex, automatic pagination or scope broadening is used. Competitors exclude the requested hostname and its www alias; major domains are not silently excluded. Clickstream and synonym removal are disabled. An overview request returns at most one market record; its result count is not a keyword count.

In the competitor contract, `full_domain_metrics.organic` describes the competitor; `metrics.organic` describes the target on the shared keywords. The normalized fields `fullDomain` and `targetOverlap` retain these distinct populations. Average position is not the competitor's average across all keywords. There is no calculated competition score, share-of-traffic percentage or authority rating. Position buckets retain their12 provider categories, from rank1 through ranks91–100; missing fields stay null. `estimated_paid_traffic_cost` is the estimated advertising equivalent of organic traffic, not an incurred charge. Retrieval time is the saved observation time, not proof the provider refreshed its underlying index then.

Contracts and account-price shapes were inspected on2026-10-16. Each quote reads the selected endpoint's `price.dataforseo_labs.<endpoint>.live.priority_normal` per-request and per-result units from User Data. The worker checks that the current account's maximum price still fits the quoted ceiling before dispatch; the shared spending gate independently checks the current saved-connection cap. Missing or unsupported prices prevent work; no public example price, cached guessed price or paid fallback is used.

## Native API and paid authority

All routes require current browser sign-in and project membership; API keys have no paid scope. All four roles read setup/history/results. Owners, administrators and editors may refresh the free shared market catalog, quote and start. Only the initiating writer or an owner may cancel an undispatched reservation. Only an owner reconciles an uncertain charge. POST Origin must equal APP_URL. Unknown fields, query parameters and request bodies over8192 UTF-8 bytes are rejected. Reads are120/user/minute, writes10/user/minute and reconciliation3/project/minute.

`/api/projects/:projectId/domain-research` returns the shared catalog, current connections, spending pause and last20 receipts across profiles. POST `/catalog` accepts `{connectionId}`. POST `/quote` accepts `{connectionId,target,scope,locationCode,languageCode,limit,report?}` and returns account-derived exact prices, maximum estimate, canonical request and a five-minute expiry. POST `/runs` accepts `{quoteId,requestKey}`. GET `/runs/:id` reads retained content. POST `/runs/:id/cancel` accepts `{}`; POST `/runs/:id/reconcile` accepts `{connectionId}`.

GET `/runs/:id/export` returns bounded native JSON `{role,run,csv,rowCount}`. `run` is a summary-only acknowledgement bound to the same receipt; CSV contains exactly its retained rows and target/scope/market/source/retrieval/partial metadata. It uses the existing spreadsheet-formula escaping helper, preserves null as Unavailable and0 as0, checks current membership and retention inside the same read transaction, and makes no provider call. Unavailable or expired content returns409; exceeding the complete2MiB response limit returns413. The browser must verify the returned receipt before downloading; no stored draft can relabel an export.

Start, same-key replay, cancellation and reconciliation return bounded **summary-only acknowledgements**, even for a completed run. Content is fetched separately. A failed result GET cannot turn a verified Start acknowledgement into an uncertain paid action. Complete JSON responses are bounded to2MiB; excess is an explicit413, with no truncation. The same request UUID and quote are retained after an unconfirmed Start; only an explicit user retry resends that identical action. Reusing a key for different work is rejected. No automatic paid retry, fallback, schedule or healthcheck request exists.

## Storage, jobs and retention

Migration0048 adds separate quote/run tables with compound workspace/project/user FKs and the provider ledger identity. The shared keyword market catalog and credential vault are reused. Quotes use one database timestamp for creation/price/expiry and only abandonable unused quotes expire after24h. Used quotes, immutable request identity and financial receipts remain. New account fingerprints use existing version2 recovery keys, including key-loss detection and rekey behavior; account identity is never exposed to the browser.

Workspace then project locks recheck current role, connection revision, quote expiry and provider budget before dispatch. Free metadata happens outside those locks, followed by fresh checks. One free30s account verification and one paid30s request fit a90s no-retry queue job; a lost dispatch becomes uncertain after120s. These are bounds for this queue, not changes to keyword/rank jobs. Organic reports admit only the four fixed Labs endpoints; the separate Backlinks profiles admit their two fixed endpoints. An unknown cost pauses spending and keeps the original task identity; exact endpoint/account/tag/payload matching uses the existing28-day metadata window, rejects ambiguous/incomplete1000-row inventories and rechecks age after waits. A known malformed result retains its known charge; reported overruns retain the charge and pause subsequent work. Per-connection monthly caps and the master pause remain; there is no aggregate workspace monetary cap or feature paywall.

No migration is required for these profiles: migration0048 already stores immutable request and result objects. The shared queue, cancellation, lost-dispatch reconciliation and bounded retention paths cover every profile. Only unused quotes expire; the original report profile, quote identity and financial receipt remain after result purge. Reconciliation of one endpoint cannot settle another endpoint's receipt.

Results use current derived-history retention. One fresh materialized database clock after authority locks governs both visibility and the expired flag. Current-policy expiry hides rows before cleanup; extending that policy before physical purge can make still-stored older observations visible in a fresh read. The mounted UI keeps an already-observed expiry latched. The bounded retention pass clears100 results/unused quotes per iteration, never used quotes or ledger evidence. Physically purged content is never restored. Replay/reconciliation never creates new content or resets its observation time.
