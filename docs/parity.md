## Release evidence and unresolved boundary

Each row needs a source-contract mapping, runnable acceptance check, observed result and relevant failure/authorization checks. Provider-backed rows need contract fixtures plus a deliberately budgeted real integration smoke test; a mocked successful response alone is not provider validation. Cross-cutting authorization, persistence, restart, export and accessibility checks apply to every affected row.

The owner explicitly excluded SaaS subscription sales: ten98-monitor is free and fully featured for everyone. P65 verifies removal of upstream checkout/dunning/seat/plan gates while P64 preserves external provider spending and workspace budgets. This explicit scope choice does not exclude hosted technical functions such as sharing, team creation, SSO or branding in Docker.

Full parity means a complete capability and observable-behavior mapping, not pixel-identical screens or identical implementation internals. Internal milestone completion, scaffolded routes, disabled menu items, empty provider results, and `planned` rows do not constitute release parity. Do not publish a full-parity release claim until every row is verified or the user has explicitly approved a documented baseline change.
