Layout/behavior:

1. Outer `section.research-panel`, labelled by `<h2 id={idPrefix+'heading'} tabIndex={-1}>Rank schedule</h2>`. Subtitle trackerName. Back button typebutton calls onBack, disabled only locked. Refresh button disabled locked/working/loading, calls onRefresh. Busy status in `role=status`: loading is “Loading schedule…”; working is “Saving schedule…” (preview is loading, not working). Nonempty error uses rolealert; notice rolestatus.
2. Pending outcome has prominent alert: “The outcome is unknown. Retry the same request to recover its receipt. Do not create another approval.” Button “Retry same request” calls onRetry, disabled working. Preserve this surface even when schedule/quote is absent or expired. All edit controls and other actions are disabled through locked. Conflict copy: “The tracker changed. Reload before approving another schedule.” Existing Refresh is the recovery action.
3. If schedule exists, show current status: enabled && !approvalStale = “Approved schedule”; enabled && approvalStale = “Approval needs review”; !enabled = “Schedule disabled”. Show schedule interval, timezone, hour/minute and weekly weekday, nextDueAt (raw ISO string with explicit UTC label; null = “Not scheduled”). When approval exists show maximumUsd USD per occurrence, connectionName or “Saved provider connection”, and approvedAt or “Not recorded”. Do not expose internal UUID/user IDs. Map stale reasons: disabled→“Schedule is disabled.”; archived→“Tracker is archived.”; approver_no_longer_owner→“The approving user is no longer an owner.”; connection_changed→“The provider connection changed.”; definition_changed→“The tracked definition changed.” Unknown reason→“Approval needs a fresh review.” Disable button only canManage, disabled !canDisable||locked||working, label “Disable schedule”. Copy: “Disabling stops future scheduled requests, including work not yet sent. Requests already sent and their charges remain.” No deletion control.
4. Nonowner with loaded schedule: “Only workspace owners can approve or disable recurring spending.” No owner form or quote action. When schedule is null, do not display an invented disabled grant or owner form; show loading/error state with Refresh.
5. Owner without quote and with schedule: a single “Prepare full queued quote” button calls onPrepareQuote, disabled locked/working/loading. Explain a full queued quote is required to approve or renew a schedule; merely viewing the screen starts no check. Owner with quote: display targetText (already formatted by controller), taskCount keyword/device checks, estimateUsd USD quoted maximum, expiresAt with UTC label, and expired message “This quote expired. Prepare another full queued quote.” If expired show Prepare full queued quote button, but pending retry remains available above and locked prevents navigating away. Keep quote summary visible while editing. No actual Start check button.
6. Owner + schedule + quote displays one native form; onSubmit preventDefault then onPreview (so Enter previews, never approves recurring spending). Fieldset disabled locked||working||loading||quote.expired||conflict. Interval select Daily/Weekly/Month end. Timezone text input maxLength100, visible label “Timezone”, helper “Use a PostgreSQL timezone name, such as America/New_York.” Hour numeric input min0 max23 step1; minute min0 max59 step1, raw controlled strings. Weekly shows weekday select Sunday0..Saturday6; hide it otherwise. Changing interval uses onChange preserving other form fields except consent:false (controller normalizes weekday and invalidates preview). Month end helper “Runs on the last calendar day in the selected timezone.” All calendar changes call onChange with exact raw string values; do not validate or trim. Preview button typesubmit disabled !canPreview. Preview is free and creates no job.
7. Per-occurrence ceiling: text input inputMode=decimal maxLength14, value form.maximumUsd, helper “USD per full occurrence, at least the quoted maximum. This is not a monthly budget.” onChange clears consent. Do not convert or round with Number. Numeric validation belongs to controller.
8. If preview exists, display “Next five occurrences” table with Local time (preview.timezone), UTC, UTC offset columns. Keep returned raw strings; UTC offset format sign plus HH:MM, including seconds if nonzero historical offset (use integer arithmetic only). Show preview.capturedAt as “Calculated at … UTC”; explain “The first occurrence is recalculated when approval is saved. Daylight saving changes follow the selected timezone.” No client calendar calculations. Offsets may be negative, including half-hour and second offsets.
9. Explicit checkbox labelled “I approve recurring provider charges up to this ceiling per occurrence.” Use form.consent. Approval button typebutton labelled “Approve recurring spend”, disabled !canApprove||locked||working||loading. Explanatory copy: “Each occurrence still requires current owner approval, unchanged tracked scope and available workspace and connection budgets. Saving approval does not run a check immediately.” Buttons never invoke callbacks while their disabled condition holds. No auto-enable, automatic quote, scheduled fetch or provider call.
