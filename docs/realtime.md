# Native realtime analytics contract

This is an incremental native traffic read for P32, not complete realtime/geography parity or a V1 release. The shared browser/server DTO is `src/lib/realtime.ts`; the reader is `src/server/realtime.ts`. No provider calls, job, websocket, cache table or migration is involved.

`GET /api/projects/:projectId/realtime` requires a current browser session/workspace membership, or a current workspace API key with `analytics:read`. Owners, admins, editors and viewers can read. The fixed request accepts no query parameters or body; other methods return 405. Responses use the existing JSON `no-store`/`nosniff` headers. The existing per-user read limit is 60 requests/minute; API-key requests retain their shared key limit. Unknown/missing projects and cross-workspace reads return 404, missing/expired credentials 401, insufficient key scope 403, malformed request 400 and bounded database timeout 503.

The reader follows the existing session-report workspace SHARE gate and refreshes API-key authority after waiting. A single materialized raw database instant determines final key expiry; its millisecond-truncated value determines the emitted `asOf` and all metric bounds. Current membership and key scope/revocation/expiry are checked again in that report statement. The transaction sets UTC locally, a five-second lock timeout and five-second statement timeout before the gate; those settings do not change worker/management transactions or connection defaults.

## Windows, coverage and identity

The period is exactly `[asOf - 1800 seconds, asOf)`. The active window is exactly `[asOf - 300 seconds, asOf)`. Both are UTC and exclude future observations. Up to 31 minute buckets cover the entire rolling period without gaps: first/last bucket bounds are clipped to the period, and `partial` marks a bucket shorter than 60 seconds. Bucket counts and full period counts use the same snapshot. `start`/`end`/`asOf` have millisecond ISO precision; activity `receivedAt` preserves canonical six-digit PostgreSQL microseconds and sorts by that exact timestamp, then ID descending. A client must not derive ID ordering from timestamps rounded to milliseconds.

The population is all retained records from the native `event` table, including browser, authenticated API and legacy observations; imported-provider tables are separate. Effective retention is the greater of the saved irreversible analytics watermark and the current raw-analytics policy cutoff. Whole-period and active-window coverage each report complete/partial/unavailable. A fully expired bucket or window has null counts/estimates; a partially retained bucket/window reports retained observations as incomplete. Extending the policy cannot restore a saved watermark. An available empty window has zero recorded pageviews/custom events and an empty feed, while visitor estimates remain unavailable when no stored identity supports them.

Period and minute visitor estimates count distinct stored project visitor keys **on pageviews**; active visitor estimates count keys on **any event** in the last five minutes. Identity coverage counts disclose recorded keyed and unkeyed observations for each scope. These are estimates of rotating keys, not people: monthly rotation, input/secret changes and distinct cookieless/consent namespaces can split activity. Minute estimates are nonadditive; period visitors are calculated distinctly over the full period. Turning current network identity derivation off does not erase retained historical keys; new identity-free observations cannot invent keys. Collection counts separately preserve cookieless, consent and unknown historical/API basis, and capture coverage remains unknown.

## Rankings and activity

Top 15 paths and referrer hosts count **all pageviews** in the retained period, independently of the activity limit, with descending count and deterministic fixed-C text ties. Null referrer means not recorded/unknown, never a proven direct visit. Referrer coverage describes recorded versus missing-host pageviews; valid previously normalized hosts can be up to the existing 2,048-character bound. Current optional collection settings do not relabel retained evidence.

Activity returns only the newest 100 real pageview/custom records, plus full `totalEvents` and `sampled`. It creates no synthetic session/visitor events. Each row contains scoped event ID, exact receipt time, kind/name, pathname, observed origin, nullable rotating visitor key, bounded environment fields, nullable referrer host and source/collection basis. Properties, profiles, explicit identity tokens, raw IP/user agent, query strings and fragments are not exposed. Browser/OS/device fields reuse the accepted environment version/catalog: an observed `unknown` is distinct from a null unrecorded/missing/unsupported field. A recognized environment version can have partially missing fields; older unversioned metadata does not acquire a fabricated parsed environment.

Geography uses the [native geography contract](analytics-geography.md): full-window country counts and coverage/provenance are separate from the latest-100 activity sample. Rows expose only strictly validated location observations. Missing evidence is Not recorded; a completed unmatched lookup is Unknown; expired history has unavailable/null counts. The country map uses retained observations rather than the current reader's readiness.

## Reference and checks

The flow is inspired by the pinned [Umami3.4.0 realtime route](https://github.com/umami-software/umami/blob/ec0ff50388c264ed8ce46f00967e92f7e71476ae/src/app/api/realtime/%5BwebsiteId%5D/route.ts), [realtime data assembly](https://github.com/umami-software/umami/blob/ec0ff50388c264ed8ce46f00967e92f7e71476ae/src/queries/sql/getRealtimeData.ts), [100-row activity query](https://github.com/umami-software/umami/blob/ec0ff50388c264ed8ce46f00967e92f7e71476ae/src/queries/sql/getRealtimeActivity.ts), [five-minute active query](https://github.com/umami-software/umami/blob/ec0ff50388c264ed8ce46f00967e92f7e71476ae/src/queries/sql/getActiveVisitors.ts) and [10-second polling hook](https://github.com/umami-software/umami/blob/ec0ff50388c264ed8ce46f00967e92f7e71476ae/src/components/hooks/queries/useRealtimeQuery.ts). These supplied pinned sources were inspected locally; original code reuses our existing storage/auth/retention patterns and adds no upstream application-file copy or dependency.

Necessary arithmetic differences are explicit: the reference aligns the start to a minute before subtracting30minutes; this reader uses an exact rolling30minutes. The reference sums per-minute session counts for its visitor headline and derives custom-event/path/referrer totals from its100-row sample; this reader calculates period distinct keys and all totals/rankings from the full retained population. The reference synthesizes visitor activity rows; this reader displays real events only. Geography requires actual stored lookup evidence. These choices preserve the useful card/chart/activity/ranking hierarchy, not a claim that all reference arithmetic/features are identical. UI polling/visibility/pause/status behavior and combined browser acceptance remain separately verified work.

`node --test tests/realtime.test.ts` checks the strict fixed selector. `TEN98_INTEGRATION_TEST=1 TEN98_REALTIME_TEST=1 node --env-file=<private-local-fixture> tests/realtime-integration.ts` requires a fresh migrated empty loopback PostgreSQL18 fixture on55501 named `ten98_realtime_<12hex>` (or the workflow's isolated `ten98_realtime_ci` database, migrated first), and identity network mode off. It checks empty/null semantics, exact contiguous UTC buckets on a non-UTC connection, current-role/tenant scope, actual native privacy/duplicate/environment behavior,352 observations versus the100sample, separate identity bases and nonadditive estimates, safe metadata projection, future exclusion, partial/expired retention, long referrer/partial environment, browser/API-key syntax/scope/revocation, expiry between the preliminary and report gates, and membership removal during a real lock wait. Synthetic fixtures are retained; no website crawl, paid API, customer-data, live deployment or full parity claim follows from them.
