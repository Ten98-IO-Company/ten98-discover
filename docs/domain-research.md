# Domain SEO ranked keywords

This P49 increment is a manual, paid, organic ranked-keyword lookup. It is separate from serving-domain configuration. Domain overview, ranked pages, competitor suggestions, optional rating enrichment and the remainder of P49 are still required. It is not complete OpenSEO parity.

## Scope and display

The selected target, scope, location/language and maximum25/50/100 results form an immutable quoted request. **Domain and subdomains** includes the named hostname and descendants; **Domain only** pins the named hostname, treating its `www.` alias as equivalent. **Subfolder** includes the chosen path and descendants with a path boundary; **Exact URL path** includes the exact path and its trailing-slash variant. The OpenSEO89e5 scope convention ignores query strings, fragments and HTTP/HTTPS differences, canonicalizes IDNs and treats leading `www.` as an alias. The screen discloses the canonical target before a quote and again before paid Start. Subfolder requires a non-root path. No DNS lookup or target-page fetch occurs.

The fixed request is DataForSEO Labs Google `ranked_keywords/live`, organic items only, live historical mode, offset0, clickstream disabled, absolute rank enabled, estimated-traffic descending then keyword ascending. Scope filters precede provider results; every returned URL is independently checked against the selected scope. Literal percent, underscore and backslash filter operators are escaped. A report shows returned count, provider total count and explicit partial status. A first page is never called a complete inventory when more results exist; no automatic paid pagination occurs. Provider estimates are not native visits or traffic measurements. Missing metrics are null; genuine0 remains0. CPC is exact micro-USD text, not an account charge.

The fixed endpoint and its limits/filter/tag contract are documented in [DataForSEO Ranked Keywords](https://docs.dataforseo.com/v3/dataforseo_labs-google-ranked_keywords-live/). Account-specific base per-request/per-result pricing comes from the free [User Data endpoint](https://docs.dataforseo.com/v3/appendix-user-data/); optional paid parameters are not inferred from those base prices and remain disabled. No fixed public price is hardcoded.

## Native API and paid authority

All routes require current browser sign-in and project membership; API keys have no paid scope. All four roles read setup/history/results. Owners, administrators and editors may refresh the free shared market catalog, quote and start. Only the initiating writer or an owner may cancel an undispatched reservation. Only an owner reconciles an uncertain charge. POST Origin must equal APP_URL. Unknown fields, query parameters and request bodies over8192 UTF-8 bytes are rejected. Reads are120/user/minute, writes10/user/minute and reconciliation3/project/minute.

`/api/projects/:projectId/domain-research` returns the shared catalog, current connections, spending pause and last20 receipts. POST `/catalog` accepts `{connectionId}`. POST `/quote` accepts `{connectionId,target,scope,locationCode,languageCode,limit}` and returns account-derived exact prices, maximum estimate, canonical request and a five-minute expiry. POST `/runs` accepts `{quoteId,requestKey}`. GET `/runs/:id` reads retained content. POST `/runs/:id/cancel` accepts `{}`; POST `/runs/:id/reconcile` accepts `{connectionId}`.

Start, same-key replay, cancellation and reconciliation return bounded **summary-only acknowledgements**, even for a completed run. Content is fetched separately. A failed result GET cannot turn a verified Start acknowledgement into an uncertain paid action. Complete JSON responses are bounded to2MiB; excess is an explicit413, with no truncation. The same request UUID and quote are retained after an unconfirmed Start; only an explicit user retry resends that identical action. Reusing a key for different work is rejected. No automatic paid retry, fallback, schedule or healthcheck request exists.

## Storage, jobs and retention

Migration0048 adds separate quote/run tables with compound workspace/project/user FKs and the provider ledger identity. The shared keyword market catalog and credential vault are reused. Quotes use one database timestamp for creation/price/expiry and only abandonable unused quotes expire after24h. Used quotes, immutable request identity and financial receipts remain. New account fingerprints use existing version2 recovery keys, including key-loss detection and rekey behavior; account identity is never exposed to the browser.

Workspace then project locks recheck current role, connection revision, quote expiry and provider budget before dispatch. Free metadata happens outside those locks, followed by fresh checks. One free30s account verification and one paid30s request fit a new90s no-retry queue job; a lost dispatch becomes uncertain after120s. These are bounds for this new queue, not changes to keyword/rank jobs. Only this fixed provider endpoint is admitted. An unknown cost pauses spending and keeps the original task identity; exact account/tag/payload matching uses the existing28-day metadata window, rejects ambiguous/incomplete1000-row inventories and rechecks age after waits. A known malformed result retains its known charge; reported overruns retain the charge and pause subsequent work. Per-connection monthly caps and the master pause remain; there is no aggregate workspace monetary cap or feature paywall.

Results use current derived-history retention. One fresh materialized database clock after authority locks governs both visibility and the expired flag. Current-policy expiry hides rows before cleanup; extending that policy before physical purge can make still-stored older observations visible in a fresh read. The mounted UI keeps an already-observed expiry latched. The bounded retention pass clears100 results/unused quotes per iteration, never used quotes or ledger evidence. Physically purged content is never restored. Replay/reconciliation never creates new content or resets its observation time.
