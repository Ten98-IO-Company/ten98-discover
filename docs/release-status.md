# Current implementation and release gaps

Reviewed **2026-10-13** against the published recurrence baseline `d6a3fb2` and the subsequent reporting increment recorded in [rank tracking](rank-tracking.md). Newer changes are not attributed to the earlier commit. This is the current status companion to the frozen [81-row V1 requirements register](parity.md), not a replacement or reduction of it. Later dated capability/acceptance records take precedence over an older milestone's “pending” wording.

**This is a development build, not the full V1 release.** Useful analytics, research, reporting and audit workflows exist. Every remaining sub-capability and release gate below stays required. A configured but empty screen, schema/parser alone, mock success, or absent provider credentials cannot satisfy a feature requirement.

## How to read the status

- **Implemented locally:** the named capability is present with recorded local acceptance. This is not live-provider, production-capacity or full-release certification.
- **Partial:** a usable slice or explicit implementation foundation exists, but the grouped requirement still has missing functions. The table identifies both.
- **Pending:** no usable workflow for this requirement is present. Related infrastructure is not counted as implementation.

**Evidence levels:** `L` means recorded unit, real local PostgreSQL/API/worker and/or production-client browser checks, as specified by the linked evidence. `S` means external services, DNS, SDKs or crawl transport were synthetic/contained. `O` means a specifically documented local operational drill. A row can have L/S evidence and still require all relevant real-service acceptance before release. No blanket live-provider success is claimed here.

This review classifies **8 rows as implemented locally, 47 as partial and 26 as pending**. Rows vary greatly in size; these counts are not a completion percentage. No row is presented as unconditional release certification.

The preview includes **Analytics**, **Explore**, **Conversions**, **Recent events**, **Reports**, **Google reports**, **Site audits**, **Context**, **Prompts**, **Keywords**, **Rank tracking**, **Install tracker**, **Destinations**, **Collection and privacy**, **Domains**, and role-limited workspace settings. **Keywords → Saved keywords** is implemented. The running preview was safely upgraded to `d6a3fb2` after a verified stopped backup; existing accounts, application data and artifacts were preserved, and provider spending remains paused. It includes manual checks, run history, per-keyword comparisons and owner-approved recurring checks. No standing schedule was enabled by the upgrade. Login, retained project reads, readiness and worker health passed; no provider calls were made.

## Release acceptance still required across these rows

1. **Real integrations:** deliberately authorized/budgeted acceptance for each required model/data/browser/email/reporting adapter; real OIDC/Google grants; controlled tests of all ten browser tags, consent, ownership and delivery. Current synthetic acceptance is valuable evidence, not replacement evidence.
2. **Operations:** fresh install/upgrade/rollback/backup/restore on the actual release stack, matching encryption keys, worker interruption and schedule recovery, real HTTPS/proxy and chosen optional services. The recorded Linux-amd64 restore drill used an earlier source/schema checkpoint; it is not proof of every later adapter or platform.
3. **Complete behavior:** map each grouped row to all named source sub-capabilities, correct pending implementations, and run independent permission/tenant, loss/retry, expiry, export and accessibility checks. Measure representative production workloads instead of inferring capacity from a test timeout.
4. **Release packaging/provenance:** publish no full-parity/V1 claim or release image until the above gates and complete licensing/source-contract audit are closed. A development PR, passing CI and a local preview do not constitute the release.

## Explicit boundaries preserved

- No migration/import of legacy Elmo/Umami/OpenSEO application histories is required. Native third-party reporting imports, portable exports and backup/restore remain required.
- No SaaS subscription selling, checkout, dunning, seat licensing or app feature entitlements. Provider credentials, external costs, permissions and spending budgets remain explicit.
- Shared reports use scoped revocable URLs on the deployment's `APP_URL`; separate customer/client-domain hosting is not required. This does not exclude website serving/redirect-alias measurement.
- No required Zernio or Cloudflare dependency. Direct browser tags and separately authorized native reporting connections remain different features. Optional Cloudflare/browser/email choices stay required where the accepted contract offers them.
