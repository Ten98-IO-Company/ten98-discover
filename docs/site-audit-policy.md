# Static audit admission and pacing

This is a pure coordinator boundary for the first query-free static audit increment. It performs no DNS lookup, network request, database write, sleep, retry or permission grant. P53–P56 remain incomplete until the durable worker and remaining V1 capabilities are integrated. The implementation is original and reuses the existing `redirectUrl` validator; no dependency or upstream code was added.

## URL admission

`resolveAuditCandidate(raw, baseUrl, origin)` returns `{status: 'accepted', url}` or `{status: 'excluded', reason}`. Use it for page links, sitemap documents, sitemap entries and page/sitemap HTTP redirect targets. The selected scope must already be a canonical HTTPS domain origin, such as `https://example.com`; a path, trailing slash, fragment, query, IP address or noncanonical origin is rejected. The base must be a valid query-free URL in that exact origin. Host aliases, subdomains, port changes and HTTP downgrades do not inherit scope.

`resolveRobotsRedirect(raw, currentUrl, policyOrigin)` returns `{status: 'accepted', url, policyOrigin}` or the same exclusion shape. Only this helper permits public HTTP(S) destinations across origins. `policyOrigin` remains the original canonical HTTPS origin, including after several hops. The worker must continue interpreting the resulting policy for that original origin. The redirect destination grants no page or sitemap authority.

Both helpers enforce 2 KiB UTF-8 limits on each input and the resolved URL. Malformed Unicode and percent-encoded UTF-8, raw spaces, raw or percent-encoded control characters/backslashes, and authority user information are rejected before resolution. Reserved/local hosts, private/special IP literals, encoded authorities, shorthand IPv4, unsupported schemes and nondefault ports fail the reused redirect boundary. A public-looking hostname is only syntactically eligible: **the transport must still validate every DNS answer and pin the connection**.

An actual `?` before any fragment excludes the candidate, including an empty query. It is never removed to manufacture a query-free identity. A question mark inside the discarded fragment is harmless. `%3F` and `%2F` in paths remain encoded path data, with their original escape spelling. The standard URL resolver resolves relative references and dot segments, serializes Unicode and normalizes the authority; there is no additional path lowercasing, decoding, slash removal, query sorting or URL-equivalence heuristic. Only the fragment is removed after resolution. Empty references are explicitly excluded.

Exclusion reasons are `invalid_scope`, `invalid_base`, `invalid_input`, `too_long`, `invalid_unicode`, `invalid_characters`, `invalid_percent_encoding`, `userinfo`, `query`, `blocked_url` and `outside_origin`. Results never include the rejected value or a raw exception. The accepted query-free URL is operational crawl identity, not a blanket authorization to retain URL paths outside the audit's retention policy. Callers count exclusions and incomplete coverage; excluded candidates cannot support complete-discovery/orphan claims.

## Persisted request schedule

`planAuditRequest({nowMs, nextRequestAtMs, deadlineMs, retryAfter?})` accepts finite, nonnegative integer epoch milliseconds within the JavaScript Date range; the persisted prior schedule is a timestamp or `null`. A malformed trusted clock/input shape returns `{status: 'invalid_input'}`. Pass the response-observation time as `nowMs` when applying its Retry-After header. Subsequent dispatch still uses a fresh current time and current authorization.

The result is `{status: 'ready' | 'cannot_fit', nextRequestAtMs, retryAfter}`. The timestamp is the maximum of the previously persisted schedule, `nowMs + 1000`, and any valid Retry-After timestamp. `ready` means this schedule is strictly before the immutable run deadline, **not that a request may be dispatched now**. A timestamp equal to or beyond the deadline is `cannot_fit`; it is never clamped to create time for a request. Preserve the later timestamp when representable. An unrepresentable delay or capacity failure returns `null`, which means stop, never reset to immediate dispatch.

Retry-After accepts digit-only nonnegative delta seconds and the three HTTP-date forms. Date grammar, calendar values, weekday and case are checked; the obsolete two-digit year follows the fifty-year future interpretation. A leap second is conservatively represented by the following instant. Past dates do not override the one-second floor. Outer HTTP space/tab is allowed, but ISO dates, timezone substitutions, signed/fractional seconds, combined values and invalid dates are not accepted. These parsing rules follow [RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3) and [§5.6.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.7).

The `retryAfter` classification is `absent`, `malformed`, `delta_seconds`, `http_date` or `capacity_exceeded`. Missing/malformed values use the explicit persisted/one-second fallback. Input over the transport's 16 KiB header capacity stops; it does not take that fallback. Arbitrarily large digit-only delays within that cap remain valid delays that cannot fit. Decimal length checks and bounded BigInt arithmetic avoid overflow into an early retry.

The worker persists the resulting cooldown under its run/origin coordination lock and waits outside SQL. A restart must reuse it. Any stronger saved Crawl-delay belongs in the persisted schedule and cannot be shortened by this helper. Before dispatch, the worker freshly checks time, cancellation, lease, role/domain authority, robots permission and budgets. It separately enforces redirect counts and retry eligibility; these functions do not retry or silently expand the immutable deadline.

Eight groups cover exact-origin/relative behavior, fragment/query distinction, reserved encoded path characters, pre-normalization attacks, both 2 KiB boundaries, robots cross-origin scope isolation, all HTTP-date formats, real calendar failures, fifty-year and century boundaries, minimum/persisted pacing, exact deadline equality, past dates, malformed fallback, 16 KiB/huge numeric headers and invalid clock values.
