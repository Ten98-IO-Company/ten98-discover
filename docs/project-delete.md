# Delete one website

This is the separate P46 Delete action. Reset retains a website and its configuration; Delete removes that website, installation key, native analytics/replays/heatmaps, website-specific settings, saved prompt/rank configuration and website-specific imported/provider result records. Other websites/workspaces, tracked links/pixels, workspace provider connections and financial provider-request records remain. Workspace boards and grant definitions remain authored documents; references to the removed website become unavailable. No payment entitlement is introduced.

In Collection and privacy, an owner/admin opens Delete website, checks the current website name and types DELETE exactly. Unsaved settings or another unresolved destructive request block a new deletion. Opening or typing makes no mutation. A successful contextual acknowledgment clears the current project read identity immediately, removes the stale selector entry, navigates through the existing router and reloads the current workspace project catalog. No in-memory analytics for the deleted project can be republished by that old owner.

## Closed contract

GET/POST /api/workspaces/:workspaceId/projects/:projectId/delete is same-origin browser-cookie only, owner/admin after the workspace gate, no query or API key. POST is at most1024 UTF-8 bytes: {requestId,revision,confirmation:"DELETE"}. Revision is the existing current analytics_revision, including maximum2147483647; this operation does not increment a deleted row. GET gives current workspace authority plus an item or null. It never acknowledges a POST or discloses another workspace's target.

One READ COMMITTED transaction uses the existing W→P gates; pool acquisition5s, statement5s, lock2s, total transaction15s. Current workspace owner/admin is checked before every receipt replay. The dedicated61 project_deletion_request row has a workspace FK and no project/user FK, token, origin, public key or copied definition. Actor+workspace+project+revision+exact DELETE body are hashed through the existing canonical helper in the project.delete.v1 namespace. Identical retry after committed deletion returns the original immutable ISO6 ACK. Changed actor/body/project/revision refuses409. A new request for a missing target is404; a removed current role never replays an old acknowledgment.

The seven existing ledger-linked project families are keyword research (including saved refresh), prompt execution (including cache provenance), rank dispatch, AI suggestions, AI search, content support and domain/backlink research. Any reserved/dispatched/uncertain linked provider_request refuses409. No ledger row is cancelled, settled, rewritten or deleted by Delete. The same workspace UPDATE gate serializes reserve/dispatch/settlement and scheduled claims; captured workers must pass their existing post-lock live project/run validation before dispatch. Free preflight already in progress is not represented as a new paid dispatch.

The necessary NO ACTION/RESTRICT order breaks the recurring quote/occurrence link, removes occurrences/trackers, cache items/executions/comparisons, rank task→dispatch→run→keyword→config, suggestion runs and saved tag assignments. Existing exact-project FK cascades remove the remaining website data. This is one bounded atomic operation, not a background deletion framework: capacity/timeout/fault rolls back every deletion and the receipt. There is no partial-download or asynchronous-success claim. Existing shared read gates and final export/Explorer authority checks refuse a missing target; old installation/capture capabilities cannot resolve a deleted project.
