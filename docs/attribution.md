# Native observed Attribution contract

`GET /api/projects/:projectId/attribution` reads existing retained native evidence. Workspace owners, admins, editors and viewers can read it; current API keys require `analytics:read` for that workspace. No collection, identity, provider spending or retention setting changes occur.

## Request and authority

Use `model=first-click|last-click` (default first-click) and required atomic `conversionKind=pageview|custom`, `conversionValue`. The existing Journeys typed-step schema supplies literal page-path/custom-event validation. Existing Explorer dates, IANA timezone, activity kind, exact/typed/advanced filters and cohort revision apply to **conversion observations**. Incompatible valid conditions are empty intersections. Grouping, cursor, limit, sort, currency, identifiers, repeated/unknown parameters and request bodies are rejected. The whole serialized query is at most65,536 characters; its inherited Explorer subset retains20,000. Existing1–366 local-calendar days, DST/skipped dates and saved retention watermark semantics remain unchanged.

The report reuses `analyticsPopulation`, current cohort/session-property evidence and workspace SHARE authorization. SQL/lock ceilings are5seconds. Membership/key scope refresh after waits; the final statement checks natural key expiry against its raw database clock. Foreign/missing projects404, key401/403, invalid input400, stale cohort409, rate429, query/response ceiling503. The handler awaits the query for shared error mapping. JSON is `no-store`. `asOf` is the report/authority instant, not a new receipt-time fence or guarantee that retention workers finished.

## Assignment and metrics

Matching conversion observations count once each. Native browser rows with both visitor and visit keys establish eligible converted visitor keys and observed converting `(visitor,visit)` pairs. API/unkeyed/legacy rows remain conversion coverage; they never become synthetic users or touches. Keys are estimates, rotate monthly, differ between cookieless and consented namespaces, and may change with identity inputs. Explicit identity links never merge report keys.

For those eligible converted keys, touch candidates are **all** native keyed observations in the same project, selected local dates and saved retained range. Conversion filters/cohort do not also filter touches. A campaign-filtered conversion can therefore be assigned an earlier different campaign.

* First: earliest retained window observation at or before the key’s first matching conversion, including that conversion. This is first **observed in these dates**, never first-ever acquisition.
* Last: latest timestamp strictly before the key's latest matching conversion timestamp. It may follow an earlier conversion or itself be an earlier conversion. Equal timestamps at the latest conversion are excluded. No earlier observation is a known unassigned key, not Direct.
* Select exactly one touch per converted key. Internal navigation, an untagged self-referral (see below), is selected only when the key has no other candidate in that range; otherwise by full receipt timestamp then UUID (ascending first, descending last). A touch after the key’s first conversion is never a first-click touch. Selected-timestamp tie-key counts expose ambiguity; deterministic UUID ordering does not establish client causality.
* Repeat conversions increase event totals, not category key credits. Seven fixed dimensions (referrer, Paid ads and the five campaign values) aggregate all selected keys before returning top20 named values, ordered by credits descending then literal value COLLATE C. Full distinct-value/recorded/empty/missing/displayed/omitted counts disclose the cap.

Metadata projection guards JSON types and existing UTF-16 bounds (referrer1–2048; campaign0–200); no raw dimension/property object, identifier or witness leaves SQL. An empty stored referrer is not a valid host and counts as Not recorded; explicitly empty campaign strings retain separate Recorded empty value coverage. Paid ads values are a closed set of six labels and, like referrers, have no empty coverage: an empty stored identifier counts as Not recorded. A self-referral is a referrer host equal to the host of the observation’s own recorded origin, with the port dropped and a leading www. ignored on both sides as pinned Umami does; no other alias counts (a verified serving domain or another subdomain stays a referrer), and without a recorded origin nothing is a self-referral. It is never a credited referrer: on a selected touch it counts as Not recorded, while that touch’s campaign values still count, as in pinned Umami, which selects the touch and then ignores a referrer domain equal to the hostname. Other hosts stay literal, with no Direct or organic inference. Since owner decision D11 (2026-10-17) the tracker sends a self-referral for in-app single-page views and gives each new visitor key (an identity or consent change) its own landing view with the external referrer ([analytics measurement](analytics-measurement.md)). SDK metadata is opt-in and not sticky; absence cannot establish why a value was not recorded.

`selection.evidenceIncomplete` covers unavailable selection, partial retained history, unkeyed conversions, inherited qualification/current-property uncertainty or selected-touch timestamp ties. Missing earlier touches or a removed latest conversion can change assignment, so per-source counts/rates are **not lower bounds**. Method `historyComplete:false` and `captureCoverage:'unknown'` always apply. Shares use all observed converted keys, not the top20 sum, and are null for incomplete evidence, unavailable selection or zero denominator. They are observed shares, not conversion rates, causal credit or ROI.

Known retained empty data returns zeros/empty arrays. Positive all-unkeyed conversions retain observation/basis counts but source/key/visit values are unavailable/null. Expired/cohort/session-unavailable evidence returns null report counts, never a fabricated zero. Inherited current-property uncertainty preserves its nullable unidentified-count contract. Location provenance, when geography participates in report/qualification filters, covers actual **matching conversion observations**, not attributed touches, identified users or qualification-event builds. This known observation provenance remains available when identity alone is unavailable; it becomes null when retention/cohort/session uncertainty makes the conversion selection itself unavailable.

The complete response is capped2MiB; overflow fails503, never successful hidden truncation. No new dependency, table, job, cache or service. The raw-query five-second ceiling is deliberate; measured rollups are the upgrade path if real indexed populations outgrow it.

## Source and remaining requirements

Pinned Umami3.4.0 `ec0ff50388c264ed8ce46f00967e92f7e71476ae`, `getAttribution.ts`, attribution routes/schema, `AttributionPage`/`Attribution` and query/value-selector hooks inform the flow. Its converted-key grouping, strict last-before-latest conversion and unfiltered touch pool are retained. Intentional corrections are one coherent snapshot, one deterministic credit instead of timestamp-tie fanout, full denominators/top20 coverage, accurate observed-key/event/visit labels and explicit missing evidence. Choosing another touch before internal navigation is a declared native difference for both models and all seven dimensions: last-click can still credit the landing referrer and UTM values of a single-page journey where Umami’s touch would carry none, and first-click can credit a later external touch up to the first conversion when the window starts with internal navigation. The revenue report instead keeps each key’s first observation, so the two reports can name different sources for one key. This is not identical algorithm parity.

Paid ads follows owner decision D1 (2026-10-17) and pinned Umami's `getAttribution.ts`. With campaign capture on, page views and custom events that carry the analytics grant store the six raw click identifiers Umami stores (`gclid`, `fbclid`, `msclkid`, `ttclid`, `li_fat_id`, `twclid`) in their own nullable varchar(255) event columns (migration 0065), never in the dimensions JSON and never as an identity input. The selected touch's first non-empty identifier in Umami's order names Google Ads, Facebook / Meta, Microsoft Ads, TikTok Ads, LinkedIn Ads or Twitter Ads (X); only that closed label leaves SQL. Raw identifiers are never returned, filtered, grouped, exported, shared or exposed through OpenAPI or MCP. Empty, absent, capture-off, cookieless, API and pre-0065 events count as Not recorded, never unpaid. Presence is not verified with the ad platform, so a copied or forged parameter counts, and UTM values alone never name a paid platform. Retention, reset and website deletion erase the identifiers with their event rows: a reset advances the cutoff, which hides older rows at once, and the bounded retention batches then delete them.

Consent on upgrade: with campaign capture on, an analytics grant now also covers the six raw click identifiers, so a grant given under the earlier notice must not carry over. Migration 0065 therefore rotates the consent epoch of every project whose campaign capture is on (as a settings save or collection-scope change already does), and the built-in notice is shown again with its new click-identifier sentence before any identifier is stored. Expected side effects on those projects, once at upgrade: stored analytics and replay grants and signed visit contexts are invalidated, so returning visitors are asked again and replay or heatmap capture waits for a new grant. **Operators using an existing consent platform** (`consentMode: external`) get no notice from ten98, and the rotation cannot re-prompt them: the platform re-sends the grant it stored under its own purpose text. Before upgrading such a site with campaign capture on, update that platform's analytics disclosure to cover ad click identifiers and re-collect consent, or turn campaign capture off.

Declared differences from pinned Umami's click-ID contract: (1) Umami has no consent model or capture setting and stores click IDs on every page view and custom event; ten98 stores them only when the project's campaign capture is on (off by default) and only for browser events with the analytics grant, as the [tracking contract](tracking.md) allows click IDs only under applicable permissions and the cookieless visitor notice promises basic analytics without a grant, so cookieless basic collection and `events:write` API observations never carry them. (2) Umami's short-link (`/q`) and pixel (`/p`) hits also store click IDs from their request URL; ten98 [tracked links and pixels](tracked-assets.md) store no query values. (3) Umami ships a manual backfill from its stored `url_query`; ten98 never stored query strings, so events recorded before 0065 stay Not recorded. (4) Umami counts distinct sessions over a timestamp join of its model touches; ten98 credits one selected touch per converted key, like every other dimension here. (5) Umami truncates to 255 UTF-16 units; the tracker and collector here truncate to 255 code points, identical for ASCII identifiers. (6) Umami's separate Channels and Revenue paid class matches the raw URL query against another parameter list (without `fbclid`); ten98 neither stores the query nor reproduces that class, so revenue channels are unchanged.

The project Attribution panel separates staged conversion/model/date/filter settings from its applied URL. Initial empty selection does not fetch. It verifies saved cohort revisions explicitly, rejects contradictory or incomplete transport payloads, and binds results to the current navigation entry. Known empty, unavailable and incomplete evidence remain distinct; top20 source tables show full-population coverage. The runnable real-router browser check consumes unchanged synthetic PostgreSQL responses and exercises navigation, recovery, malformed/access responses and mobile/RTL layouts. The isolated compiled-parent check also exercises applied conversion/model/date links and reload through real API responses. Source conversion-value search and full source filter/cohort discovery affordances remain required until separately delivered. This increment does not complete P38, reference UI parity or the81-feature release.
