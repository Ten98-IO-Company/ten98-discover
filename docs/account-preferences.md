# Account preferences contract

`GET /api/account/preferences` reads the current fully signed-in user's name, email and saved preferences. `POST` atomically saves that user's display name, named time zone, locale and theme. The response is versioned `account-preferences-v1`, has `Cache-Control: no-store`, and contains no session credentials. The route is reached through the existing account-security handler. No user, email, password, workspace, role, image or security-setting override is accepted.

The strict POST body is `{expectedRevision, name, timeZone, locale, theme}`. Names are trimmed, limited to120 UTF-16 units, and reject controls and malformed Unicode. A time zone must be a bounded, recognized named zone; native `Intl` canonicalizes accepted aliases. Locale must be one of the54 IDs preserved from the pinned Umami3.4.0 inventory. `ga-ES` remains that inventory's Galician selection ID; its display-format mapping is `gl-ES`. Theme is `light`, `dark` or `system`.

Without a saved row, reads return `UTC`, `en-US`, **`light`**, revision0 and a null save timestamp. Reading defaults creates no row. The first explicit save creates revision1. A caller must submit the revision it last read; simultaneous saves serialize on the current user's row, and a stale revision returns409. An unchanged save at a positive revision returns the existing response without moving its revision or timestamp. A stale unchanged save still returns409. Revisions stop at2147483647.

Writes require the configured application Origin and a real current browser session. API keys, mixed cookie/Bearer authentication and incomplete two-factor challenges cannot access this route. The same transaction locks any bound OIDC provider, the user and the exact current unexpired session, then rechecks authentication. A disabled OIDC provider or revoked/expired session prevents the save. Every workspace role may update its own account; no workspace membership is needed to retain personal settings. A workspace owner cannot use this endpoint to update another person.

Name updates use the installed Better Auth `/update-user` implementation against the same transaction client. The preference insert/update, CAS check and response read share that transaction. A late database failure rolls back both the library's name update and the preference write; response cookies are returned only after commit. Existing account password, factor, session and OIDC routes retain their behavior. Reads/writes use separate current-user request limits120/30 per minute and the existing complete8KiB JSON reader. No provider, crawler, inference, queue or paid request is triggered.

## Browser presentation

The account menu opens Profile without requiring a workspace membership. The implemented panel edits display name, named time zone, locale and appearance, separates loading/saving/conflict/unknown-outcome states, and reloads current saved preferences before recovery. A save with an unknown response is not automatically retried. Current verified preferences supply the display name; a delayed membership refresh may update workspace roles and names while preserving that same user's verified display name. Authentication or identity changes clear personal presentation state.

Appearance defaults to light. Explicit dark or system settings apply through the current account presentation context and reset during authentication loss or logout. Account-security timestamps use the selected named time zone and locale where the local browser supports them; an unsupported local zone shows the original ISO timestamp with an unavailable-zone explanation. Wire schemas preserve bounded named time-zone strings across different runtime data versions. The server recognizes stored aliases without rewriting them on read and canonicalizes an explicitly submitted zone on save.
