# Native session explorer contract

The read-only session explorer groups matching retained events by the existing project-scoped rotating visitor key. A key is an observation estimate, not a persistent customer. Identify-only properties do not create discoverable traffic. Observed-key detail can open a separate identified-activity subview using only retained explicit event evidence; current properties remain scoped to the original observed key.

## API and authorization

GET /api/projects/:projectId/sessions accepts explicit from, to and timeZone, the existing exact/typed/advanced/current-session/cohort population, an optional exact visitorKey, pageSize (1–100, default25) and cursor. Report grouping keys are rejected. Unknown or repeated parameters fail closed. Saved definitions stage filters; Apply commits the requested population.

GET /api/projects/:projectId/sessions/:visitorKey accepts only explicit calendar range/timeZone, pageSize (default50) and cursor. Its labelled scope is all retained activity for that base key within the selected dates. List predicates do not silently constrain or expand this timeline. Current properties remain separate from event-time properties.

GET /api/projects/:projectId/sessions/:visitorKey/linked-activity accepts the same range-only parameters and a distinct linked-activity cursor. It resolves only a retained observed-key anchor inside the authorized project. There is no raw identifier, token, generation, email, predicate, export or arbitrary event-bound lookup parameter. SessionDetail returns strict linkedIdentities lookup-available/open-linked-activity or unavailable/link_evidence_unavailable metadata. Lookup availability is a retained exact-key assignment existence check gated by membership and final-statement API-key validity; it does not promise verified events or complete history for the dates. Legacy-only and one-key assignments can be checked.

The explicit-identified-activity-v1 response combines only browser events carrying forward evidence version1, on directly matching project/version/generation/token assignments. Each event must meet its own assignment's exact first-acceptance fence, the project evidence start, selected calendar dates, the fixed exclusive page bound, and fresh logical raw/event/link retention cutoffs. No anonymous, off-period, legacy or transitive backfill is performed. Secret generations never join. Retained eligible history remains readable when new linking is disabled.

Counts describe qualified observations, keys and visits by (visitorKey,visitKey), never authenticated people or devices. NULL-marker candidates are counted separately as excluded unproven observations within the same retained fenced population. Unavailable link/event evidence returns NULL summary/activity and no identity reference or cursor. A readable empty qualified population returns zero counts and NULL first/last/span. Every response declares historyComplete:false and legacyEvidence:not_backfilled; coverage warnings describe clipping, excluded observations, project-wide saved loss and disabled linking.

The final authorized statement computes anchor, edges, events, exact counts, page and coverage together. Linked cursors additionally bind the anchor version/generation/token/exact first fence through a server-derived hash; the cursor carries no token or generation. An expired/renewed anchor or retention-policy change invalidates continuation with409. Other edge expiry narrows current pages under fresh retention and can produce a changed-evidence notice; fixed upper event bounds do not make a multi-request database snapshot. The existing 100-row page maximum has no silent 500-event total ceiling. No merged profile properties are returned.

All workspace members can read; API keys require analytics:read on the exact GET routes. The service holds one workspace SHARE gate in READ COMMITTED, rechecks membership/key/cohort after admission and validates key expiry again inside the final data statement. No public shares, mutation permissions or customer search oracle are added.

## Snapshot and retention

The final statement owns population, calendar bounds, event/profile/candidate evidence, totals, page rows and properties. Event history, identifier coverage and current-property evidence are independent. Unavailable selections return null rows/counts, never empty zeroes. Missing-property selection after known evidence loss remains unavailable even with zero candidates. No read refreshes profile or identity evidence.

List order is latest matching event descending then full visitor key ascending. Activity order is receive time descending then event UUID descending. Strict opaque cursors preserve database microseconds and bind project, route, key, canonical population/range and page size. An initial exclusive event bound prevents later arrivals from displacing the page start; each page still reads current properties and retained evidence. This is not an immutable multi-page snapshot.

Explicit retention saves invalidate paging through the existing workspace revision, including shrink then expand. Automatic marker movement and natural expiry return fresh coverage/evidence instead. Every page enforces current monotonic cutoffs; no cursor can restore expired data. Query and lock deadlines produce retryable503; invalid SQL regex produces400.

## Client and verification

Browser links contain only validated project/workspace, dates/timezone, selected key, optional activity=identified and definition ID/revision references. Arbitrary property/filter values stay in mounted-page state. Activity dates stage in separate native inputs until Apply; the originating list filters and page remain separate. Observed and identified cursors have distinct render-validated scopes. Source-key inspection retains one bounded linked return context without caching payloads; returning revalidates authority. Reloaded links do not claim to recover unsaved filters. Access loss clears results, cursor scopes, references and copy state. Linked409 requires explicit page-one reload. Typed properties, paths and dimensions render as inert text; identity references are copyable only on explicit action and never enter navigation. Post-render focus restores the originating action or results heading. These contracts do not certify production acceptance or full reference parity.
