# Native custom board backend

This is the persistent backend and data contract for P43, not acceptance of the full board UI or mixed-entity parity. The closed17-family registry follows the pinned Umami3.4 registry at `ec0ff50388c264ed8ce46f00967e92f7e71476ae3`, `src/app/(main)/boards/boardComponentRegistry.tsx`. Its compatible entity families are retained, but native links/pixels require the separate P44 implementation. No paid provider/import is called by a board read or save.

## Configuration and writes

`src/lib/boards.ts` defines the browser-safe strict schemas and types. Version1 has a name, description, optional default entity, canonical applied scope, and ordered rows. Rows contain a stable UUID, a minimum height150–600 and one to four nullable card slots. Up to40 actual cards and40 rows are allowed; this is a per-document bound, not a lifetime board count. Row/card IDs are unique within one board. Optional per-card literal title(1–120 trimmed characters) and description(0–1000) apply to all17 families, including TextBlock. Optional row widths contain one positive integer percentage per slot, totalling100; omission preserves equal legacy widths and unchanged historical canonical JSON. Order and minimum height are stored as authored; no arbitrary CSS, component props, HTML or remote embeds are accepted. TextBlock is literal text. Entity overrides may be website, link or pixel; `entity:null` inherits the default. A data card needs an effective entity. Website-only families and link/pixel metric restrictions are validated.

Migration0057 adds only `custom_board` and `custom_board_request`. Boards belong to a workspace because a mixed board has no required website. The latter table retains actor, request UUID, operation, canonical input hash and result ID/revision, never authored content. It survives board deletion until its workspace is deleted. New table timestamps have millisecond precision, so the existing scoped content cursor loses no native precision and survives a deleted page anchor. No project receipt is repurposed with a fake anchor, and no card table or separate ACL exists.

All routes require the current signed-in cookie. All four workspace roles read; owner/admin/editor write. POST retains the application's exact Origin and strict JSON guards. API keys, share links and replay capabilities grant no board access. Workspace locks serialize changes and recheck membership after waits. An unchanged reference to a deleted website/analysis can remain authored; reading it cannot recover its old data. New website/analysis references must belong to the current workspace and use the current saved analysis revision.

Writes return `{workspaceId,role,ack,item,deleted,replayed}`. The ACK's requestId/operation/boardId/appliedRevision identify the committed operation, independently of the current item. An exact actor/body retry returns that ACK even after subsequent edits or deletion. A clone retry cannot create another clone. Reusing a UUID for another actor, operation or canonical body is409. CAS mismatches and revision exhaustion are409. Never infer a write ACK from a similar GET or clear an unknown write's exact body/key during a refresh.

Board JSON writes are bounded to196608 UTF-8 bytes; the read-only preview body to51200 bytes, with the canonical scope and complete normalized body revalidated. Complete responses are bounded to2097152 bytes. Preview echoes its full canonical request and previewId alongside the current card context and data/outcome. Clients must validate both identities plus current user/workspace/read generation before publishing any role or data. Preview never clears a pending write or substitutes for its ACK. Read/write rates are120/30 per signed-in user per minute. Per-statement/lock timeouts are5seconds, not a whole-request deadline. Existing native readers own their own connections and authority. Board admission releases its client before those readers run, then a fresh workspace gate checks the same board revision, current entity/membership and exact retention-watermark/policy binding before publishing. This avoids pool starvation from nested client borrowing. The activity and dimension SQL readers use the gate's existing client. No background worker, automatic import or outbound network call is introduced.

## Scope and data

The stored canonical scope requires explicit `from`, `to`, `timeZone`, with1–366 inclusive days. It accepts the existing Explorer exact fields and typed event-property filter. Kind and grouping belong to the family and cannot be injected by global scope. Advanced predicates, session properties and cohorts are currently refused rather than dropped. Both the outer wire and nested scope undergo strict percent/UTF-8 validation before URLSearchParams; literal `%25` and actual replacement-character text remain valid. Empty literal fields and typed zero/false/null/missing keep their native meaning. Dates are explicit; no default calendar can drift on reload.

Each card response echoes workspace, board ID/revision, card ID/type, effective entity, current role, canonical scope and historical/fixed-live/none window. A ready response has a source discriminator and native payload. An unsupported response has one of `entity_dependency`, `scope`, `not_collected`, `reader_unavailable`, with no substituted data. Expiry/partial history and unknown identity remain native metadata; unavailable never becomes an invented zero.

## Native link and pixel cards (requires actual migration0058)
Boards reuse the P44 request report for metrics, trend, dimension table and country map. Link values describe accepted redirect requests; pixel values describe accepted image loads. Monthly asset-scoped visitor estimates and hourly visit estimates are not people, website sessions, delivery or email opens. There are no fabricated pageviews, bounce rates or revenue.

The same native dispatcher serves saved cards and explicit unsaved previews. Exact workspace and entity kind must match; new or changed references require a current scoped asset. ## Scoped website summary (private proposed successor, not executed)

The board summary reuses the single Analytics visit/count/bounce/duration SQL core. Browser/API/MCP Analytics query grammar, UTC range, result fields and JSON key order remain unchanged. This successor intentionally corrects filtered bounce values in both periods; the earlier extraction-only byte-expansion claim applies only to the immutable mixed-summary-v2 proposal. The board-only result has version native-board-summary-v1, project identity, exact canonical applied scope, native named-timezone start/end and retention coverage; it is not represented as the wide UTC Analytics report.

Counts use selected retained observations. Visits are keyed by both visitor and visit IDs; duration is the selected pageview span, averaged per observed visit. A same-visit custom event anywhere in the authorized retained date window suppresses a one-selected-pageview bounce, even when report filters exclude that custom event. Analytics summary, its dimension/environment/geography metrics, and board summaries now use the retained-custom visit rule already used by P36. P36 still withholds bounce/duration for partial retention; Analytics and board summaries describe retained-population values under their explicit partial coverage. This availability difference is preserved, not claimed as reconciled.

The summary read owns one5-second bounded client transaction after admission releases its client, then releases before the existing fresh final workspace/membership/board revision/entity/retention publication gate. It never holds two clients, streams a partial result or publishes before that gate. Original native held-event-lock membership and retention race assertions are preserved verbatim.
